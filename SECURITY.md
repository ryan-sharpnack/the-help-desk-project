# Security Policy

## Our Commitment to Security

The Help Desk Project takes the security and privacy of its contributors seriously.

Although this repository primarily focuses on educational documentation, homelab environments, and IT support scenarios, contributions may include scripts, configuration files, technical examples, and other materials that could introduce security risks.

We encourage responsible security practices in every contribution.

## Supported Versions

The latest version of the repository's main branch is the primary supported version.

Older versions and archived contributions may not receive ongoing maintenance or security updates.

## Reporting a Security Vulnerability

If you discover a security vulnerability involving this repository, its scripts, or its associated infrastructure, please report it privately.

**Do not disclose exploitable vulnerabilities through public GitHub Issues or Discussions.**

Use GitHub's Private Vulnerability Reporting feature for this repository.

Please include:

- A description of the potential vulnerability.
- The affected file, component, or configuration.
- Steps to reproduce the issue, if applicable.
- Potential impact.
- Suggested remediation, if known.

Please do not publicly disclose the vulnerability until the maintainers have had a reasonable opportunity to investigate and address it.

## Security Expectations for Contributors

Contributors must never submit:

- Passwords or authentication credentials.
- API keys or access tokens.
- Private SSH keys or certificates.
- Personally identifiable information.
- Confidential company information.
- Sensitive network configurations.
- Unredacted logs containing private information.

Before submitting technical documentation, inspect screenshots, terminal output, configuration files, and scripts for sensitive information.

## Homelab Security

When sharing homelab environments and technical exercises:

- Use fictional or anonymized account information.
- Never expose administrative credentials.
- Avoid publishing publicly accessible management interfaces.
- Remove sensitive IP addressing and infrastructure details where appropriate.
- Use isolated environments for potentially dangerous experiments.
- Clearly identify destructive commands and potentially disruptive configurations.

## Educational and Experimental Code

Scripts and configurations shared through this project are intended for educational purposes unless otherwise specified.

Contributors should explain potentially destructive operations and document relevant security implications.

Never submit malware, credential theft tools, unauthorized access mechanisms, or instructions intended to compromise systems without authorization.

All testing must be conducted in environments you own or have explicit permission to assess.

## Response and Remediation

Project maintainers will review reported vulnerabilities and determine appropriate remediation steps.

Depending on the circumstances, maintainers may:

- Remove vulnerable files or documentation.
- Request corrective changes.
- Publish updated versions.
- Notify affected contributors.
- Take additional steps to protect the community.

We appreciate responsible security research and disclosure.

**Security is everyone's responsibility.**
